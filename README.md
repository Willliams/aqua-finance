# Финансы — чек (PWA)

Учёт финансов в стиле кассового чека / e-ink. Один статический сайт, без сборки и бэкенда — все данные хранятся локально в браузере (localStorage).

## Структура

```
pwa/
  index.html   — само приложение (вся логика внутри, без зависимостей)
  manifest.json — веб-манифест PWA (иконки, имя, цвета)
  sw.js         — service worker для офлайн-кэша
  icons/        — иконки 192x192, 512x512, 512x512 maskable
  .nojekyll     — отключает обработку Jekyll на GitHub Pages
```

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub и залейте содержимое папки `pwa/` в корень репозитория (или в ветку `gh-pages` / папку `/docs` — как удобнее).
2. В настройках репозитория: `Settings → Pages → Source` — выберите ветку и папку, из которой будет собираться сайт.
3. Через 1-2 минуты сайт будет доступен по адресу вида `https://<username>.github.io/<repo>/`.
4. Откройте адрес на телефоне (Android/Chrome) — появится предложение «Добавить на главный экран», это и есть установка PWA.

Важно: `index.html` ссылается на `manifest.json`, `sw.js` и `icons/*` относительными путями (`./`), поэтому работает и в корне домена, и в подпапке репозитория на GitHub Pages — менять пути не нужно.

## Проверка PWA

- Chrome DevTools → вкладка **Application** → Manifest / Service Workers — там должно быть видно, что манифест и воркер подключились без ошибок.
- Вкладка **Lighthouse** → категория PWA → Analyze — покажет, чего не хватает до полного соответствия критериям PWA (обычно на этом этапе всё уже зелёное).
- Отключите сеть (Network → Offline в DevTools) и обновите страницу — приложение должно открыться из кэша.

## Следующий шаг — TWA (для Google Play)

Когда PWA будет опубликована на реальном HTTPS-домене (GitHub Pages подходит):

1. Установите Bubblewrap: `npm install -g @bubblewrap/cli`
2. `bubblewrap init --manifest https://<username>.github.io/<repo>/manifest.json`
3. Настройте Digital Asset Links — Bubblewrap подскажет, что добавить в `assetlinks.json`, файл должен быть доступен по адресу `https://<домен>/.well-known/assetlinks.json`.
4. `bubblewrap build` — соберёт Android-проект (AAB), который можно подписать и загрузить в Google Play Console.

## Известные ограничения текущей версии

- Все данные хранятся только в localStorage конкретного браузера/устройства — синхронизации между устройствами нет (для этого нужен бэкенд, это отдельный этап).
- Экспорт/импорт данных (JSON) есть в Настройках — используйте для переноса на другое устройство или резервной копии.
- Фото чеков хранятся как base64 внутри localStorage — при большом количестве чеков это может упереться в лимит хранилища браузера (обычно 5-10 МБ). Для продакшена стоит перейти на IndexedDB для файлов.
